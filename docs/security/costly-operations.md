# Costly operations

One inventory of Ariva's resource-demanding operations: what makes each costly, the bounds that hold it, its timeouts, its rate limit or concurrency limit, where each is set and the test that proves it. For a site's operations team sizing a deployment, for reviewers of a change that adds a read, an upload, a job or a consumer, and for the availability defences of [asvs-l2](asvs-l2.md) V15.2.2.

Status: this page describes the code as of 2026-10-19 (ARV-095). It changes no limit. Section 15 lists the costly operations with no limit or no timeout; ARV-096 adds request timeouts and a concurrency policy to the on-demand report and CSV endpoints.

## 1. Purpose and how to read it

This page serves ASVS 5.0 V15.1.3 (document resource-demanding functionality and its availability defences). It gathers what other pages give feature by feature: the file uploads in [wiki 13a](../../wiki/13a-File-Handling.md), the Integration API's batches and AIDX in [integration](../architecture/integration.md), floor plans in `security/README.md`, and the measured bounds in `docs/product/decisions.md` (ARV-104g, points 1 and 8; ARV-123a, point 5).

Columns:
- **Cost driver**: what grows with the input or the data (memory, rows read, CPU, time held).
- **Limit**: the bound on that driver. "Refused" means a request over the bound gets an error rather than a cut answer; "cut" means the answer is marked as truncated.
- **Timeout**: what ends the operation if it runs long. "None" means none was found in Ariva's code; the platform's defaults may still apply (section 14).
- **Rate limit or concurrency**: the policy of `Ariva.Api.Common/Extensions/RateLimitingExtensions.cs` (or another limiter) that applies on top of the global per-address limit of section 2.
- **Where set**: file and symbol, or the setting (`Section:Key`) with its default.
- Unit tests are in `Platform/Backplane/Ariva.UnitTests`, integration tests in `Platform/Backplane/Ariva.IntegrationTests`, end-to-end specs in `Platform/Testing/Ariva.E2E/tests`.

Every limiter rejection answers 429 with `Retry-After`: a window limiter's own time, or 10 seconds for a concurrency limiter, whose lease names none (`RateLimitingExtensions.ConcurrencyRetryAfterSeconds`). The rate limiting middleware runs before authentication, so floods are refused before any token work (`UseAppRateLimiting`).

## 15. No limit or timeout found

Costly operations that lack a bound, a timeout or a concurrency limit in Ariva's code today. None is fixed by this page.

1. **On-demand daily report and its CSV** (`ReportsController.Daily`, `DailyCsv`): no request timeout and no concurrency policy; only the global per-address limit. The read of `queue_minute` (every minute of every queue zone of the site for one local day, with histograms), of `zone_outage` and of `device` has no row bound (`ReportReader.ReadAsync`); it is bounded only by one day and the site's zones (a profile holds at most 500 queue zones, `ZoneProfile.MaxZones`, so at most 720,000 minutes). **Covered by ARV-096** (`AddRequestTimeouts` defaults and a concurrency policy on the on-demand report and CSV endpoints).
2. **Request timeouts on every other endpoint**: only the validation results have one (`UseRequestTimeouts` in Ariva.Api.Main, policies from `ValidationExtensions`); Ariva.Api.Ingest, Integration, Stream and Cronz map none. ARV-096 adds defaults (its criterion names the report and CSV endpoints); whether its defaults reach the other hosts' endpoints is To confirm.
3. **Reads of section 3 without a concurrency policy**: arrival wave, desk states, immigration view, overflow bands, zone health, availability, device health, advertising timeline, staffing recommendation, searches. Each bounds its rows, but none has a request timeout or a concurrency limit beyond the global per-address limit. To confirm whether ARV-096's defaults cover them.
4. **Search counts**: every paged search counts its whole filtered set (for example `SvcAuditEntries.SearchAsync`, `SvcAlerts.SearchAsync`); the audit and alert searches take no required date range, so the count grows with the table. Page size is bounded (500); the count is not.
5. **Database command timeout**: no Ariva setting for the hosts' sessions (section 14); a slow query runs to Npgsql's default (To confirm the value) and no `statement_timeout` bounds it on the server.
6. **TickerQ jobs and background loops**: no run timeout on any job or on the alert evaluation tick, the device heartbeat sweep, the idempotency sweep or the AMAN and ACRIS polls (beyond each call's own outbound timeout). Each bounds its reads; a slow database holds the run.
7. **Secret re-protection round**: reads every protected secret of the deployment in one round, with no batch bound (`SecretReprotectionRound`). Bounded by the number of accounts, clients and endpoints.
8. **Kafka consumer handlers**: no per-message handler timeout was found for the MassTransit rider endpoints (`MessagingExtensions`); a stuck handler holds one of the endpoint's 8 slots. To confirm.
9. **Live hub connections per replica**: no cap on the total, only 8 per session and the global per-address limit on negotiate (`HubSessions.MaxConnectionsPerSession`). To confirm whether a total is wanted.
10. **Backtests, display boards, advertisement fetches, integration batches and AIDX**: concurrency or rate limits exist, but no timeout. A backtest reads at most a day of 64 zones; a board at most 200 schedules; a batch at most 500 items.
11. **Not built**: the forecast job and SLA evaluation (Cronz), the Integration API's `queues:read` and `displays:read` endpoints, and the weekly summary and advertising figures endpoints (ARV-146). Their limits come with their stories.
