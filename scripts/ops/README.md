# Operations tooling (ARV-126)

Backup, restore and recovery for an Ariva deployment. Nothing here runs inside an Ariva host; the procedure is in [wiki 04 section 10](../../wiki/04-Deployment-Guide.md) and the recovery steps in [wiki 10 section 4.13](../../wiki/10-Operations-Runbook.md).

| File | Runs where | What it does |
|---|---|---|
| `ariva-ops.mjs` | An operator's machine (Node 22, kubectl, age 1.1 or later, ssh-keygen from OpenSSH 8.1 or later) | `backup` (database and files, each encrypted with age while it streams; the manifest of SHA-256 values signed with the operator's SSH key), `restore` and `files-restore` (the manifest's signature verified against an allowed-signers file kept outside the backup store before its hash is used, or a SHA-256 the operator gives from their own log; then a private copy hashed and decrypted, never the file given), `keyring` (the Data Protection keys against the certificates you hold), `check`, `after-kafka-loss`. `--plan` prints the commands; `--self-test` checks validation, argument arrays and the signed path with stand-ins for kubectl and age (run by `node scripts/verify.mjs security`) |
| `ariva-db.sh` | Inside the TimescaleDB pod (copied to `/tmp` by `ariva-ops.mjs`) | `pg_dump` and the checks as the migration login with the password the pod holds; the restore's TimescaleDB steps as the database superuser over the local socket, which TimescaleDB requires (accepted by the owner, 2026-10-15); a table of contents check before and a check after the restore for what a forged dump could leave (defence in depth; the signed manifest is the gate); the republish of the compacted topics' state from the outbox |

Rules kept by both (CWE-78, CWE-269, CWE-532): every value is checked against a strict pattern, every command is an argument array started without a shell, values reach SQL only as psql variables, no password is on a command line or passes through the operator's machine, nothing unencrypted is written outside the cluster, nothing is restored without a signed manifest or the operator's own hash, and the Data Protection certificate's private key is never read. `Ariva.UnitTests/Operations/OpsScriptTests` keeps the script in step with the code, and `Ariva.IntegrationTests/Operations/BackupRestoreTests` restores a backup into a fresh server and starts the hosts on it.
